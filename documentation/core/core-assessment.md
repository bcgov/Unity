# Core — Assessment

An assessment is one person's review of one application. An application can have many; each assessor gets at most one; and at most one is generated by AI.

Assessments are where Flex scoresheets attach, and completing them is what moves an application towards a decision.

## The aggregate

`Domain/Assessments/Assessment.cs` — `AuditedAggregateRoot<Guid>`, `IMultiTenant`, and — uniquely in the core — `IHasWorkflow<AssessmentState, AssessmentAction>`.

| Property | Notes |
|---|---|
| `ApplicationId` / `Application` | Private setter; the navigation throws if uninitialized |
| `AssessorId` | The reviewing user, or `AIScoringConstants.AiPersonId` for an AI assessment |
| `Status` | `AssessmentState` — private setter, only the workflow moves it |
| `IsComplete`, `EndDate` | Set by the workflow's entry/exit hooks, not by callers |
| `ApprovalRecommended` | The assessor's recommendation |
| `IsAiAssessment` | Marks the read-only AI record |
| `FinancialAnalysis`, `EconomicImpact`, `InclusiveGrowth`, `CleanGrowth` | Four fixed integer scores, predating Flex scoresheets |
| `Workflow` | `[NotMapped]` — the state machine instance, built in both constructors |

## The workflow lives on the entity

Unlike the application workflow, which is configured by a domain service, the assessment carries its own:

```csharp
public void ConfigureWorkflow(StateMachine<AssessmentState, AssessmentAction> stateMachine)
{
    stateMachine.Configure(AssessmentState.IN_PROGRESS)
        .Permit(AssessmentAction.Complete, AssessmentState.COMPLETED);

    // NOTE: This will be removed when there are no more assessments IN_REVIEW
    stateMachine.Configure(AssessmentState.IN_REVIEW)
        .Permit(AssessmentAction.SendBack, AssessmentState.IN_PROGRESS)
        .Permit(AssessmentAction.Complete, AssessmentState.COMPLETED);

    stateMachine.Configure(AssessmentState.COMPLETED)
        .Permit(AssessmentAction.SendBack, AssessmentState.IN_PROGRESS)
        .OnEntry(OnResolved)
        .OnExit(OnReopened);
}
```

```text
IN_PROGRESS ──Complete──▶ COMPLETED ──SendBack──▶ IN_PROGRESS
                              ▲
IN_REVIEW ────Complete────────┘        (deprecated — no path leads into IN_REVIEW)
IN_REVIEW ────SendBack────▶ IN_PROGRESS
```

`IN_REVIEW` is a legacy state kept only so existing rows remain valid; its own comment says it will be removed once none are left. Nothing transitions *into* it.

The entry and exit hooks are the only place `IsComplete` and `EndDate` are written:

```csharp
private void OnResolved()  { EndDate = DateTime.UtcNow; IsComplete = true; }
private void OnReopened()  { EndDate = null; }
```

Note the asymmetry: reopening clears `EndDate` but leaves `IsComplete` true.

The `AssessmentAction` enum declares three values — `Create`, `SendBack`, `Complete` — but `Create` is never configured as a trigger; assessments are created through the manager, not by firing an action.

## Creating an assessment

`AssessmentManager.CreateAsync(application, assessorUser)` enforces two domain rules before anything is written:

| Rule | Error |
|---|---|
| A user cannot hold two assessments on one application | `AssessmentUserAssignmentAlreadyExists` |
| An application in a final decision state cannot be assessed | `CantCreateAssessmentForFinalStateApplication` |

Then three things happen in order:

```csharp
var otherAssessments  = await _assessmentRepository.GetListByApplicationId(application.Id);
bool hasOtherAssessments = otherAssessments != null && otherAssessments.Any(a => !a.IsAiAssessment);

var assessment = await _assessmentRepository.InsertAsync(
    new Assessment(GuidGenerator.Create(), application.Id, assessorUser.Id), autoSave: true);

// 1. The FIRST human assessment moves the application into UNDER_ASSESSMENT
var isTransitionToAssessmentAllowed =
    await _applicationManager.IsActionAllowed(application, GrantApplicationAction.Internal_StartAssessment);
if (!hasOtherAssessments && isTransitionToAssessmentAllowed)
    await _applicationManager.TriggerAction(application.Id, GrantApplicationAction.Internal_StartAssessment);

// 2. A Flex scoresheet instance is created for it
if (form.ScoresheetId != null && await _featureChecker.IsEnabledAsync("Unity.Flex"))
    await _localEventBus.PublishAsync(new CreateScoresheetInstanceEto {
        ScoresheetId = form.ScoresheetId ?? Guid.Empty,
        CorrelationId = assessment.Id,
        CorrelationProvider = "Assessment",
        RelatedCorrelationId = hasOtherAssessments ? otherAssessments![0].Id : null
    });
```

Two details worth carrying:

- **`hasOtherAssessments` excludes AI assessments.** An AI assessment existing does not stop the first human assessment from moving the application to `UNDER_ASSESSMENT`.
- **`RelatedCorrelationId`** points the new scoresheet instance at the first existing assessment's instance, which is how Flex relates parallel assessments of the same application.

The transition is also guarded by `IsActionAllowed` rather than assumed — an application already past `UNDER_ASSESSMENT` gets an assessment without being dragged backwards.

## AI assessments

`AssessmentManager.CreateAiAssessmentAsync(application)` is a deliberately narrower path, called by the AI module after scoring completes (see [`ai/ai-operations.md`](../ai/ai-operations.md#application-scoring)):

| Property | Value |
|---|---|
| `AssessorId` | `AIScoringConstants.AiPersonId` — the fixed GUID `00000000-0000-0000-0000-000000000001`, one AI Scoring `Person` per tenant |
| `Status` | Created directly as `COMPLETED` |
| `IsAiAssessment` | `true` |

It differs from the human path in three ways: it is **idempotent** (returns the existing AI assessment if one exists — only one per application), it takes **no user**, and it **does not touch application state**. A Flex scoresheet instance is still created, with `RelatedCorrelationId = null`.

`AIScoringConstants` also carries the display identity: OIDC sub `ai-scoring`, name `AI Scoring`, badge `AI`.

### An AI assessment is read-only

Two guards enforce it:

```csharp
// AssessmentAppService.ExecuteAssessmentAction
if (assessment.IsAiAssessment)
    throw new BusinessException(GrantManagerDomainErrorCodes.CannotModifyAiAssessment);
```

and `AssessmentAuthorizationHandler` short-circuits on `resource.IsAiAssessment` before any ownership check.

### Cloning an AI assessment into your own

`CloneFromAiAsync(aiAssessmentId)` is how an assessor adopts the AI draft as a starting point:

1. `[Authorize(AIPermissions.Analysis.ViewScoringResult)]`, plus a runtime check that the `Unity.AI.Scoring` feature is on.
2. Rejects a non-AI source with `CannotCloneNonAiAssessment`.
3. Creates a **normal** assessment for the current user through `AssessmentManager.CreateAsync` — so all the usual rules apply, including the one-per-user rule.
4. Copies `ApprovalRecommended` across.
5. `_assessmentScoresheetService.CopyAiAnswersIfEnabledAsync(applicationId, newAssessment.Id)` copies the scoresheet answers.

The clone is an ordinary assessment owned by the assessor, editable and attributable to them.

## Executing an action

`AssessmentAppService.ExecuteAssessmentAction(assessmentId, triggerAction)` runs four checks before the transition:

```text
1. AI assessment?                    → BusinessException CannotModifyAiAssessment
2. AuthorizationService.CheckAsync(assessment, requirement)   ← resource-based
3. ValidateAnswersOnCompleteAsync    ← scoresheet completeness, on Complete
4. assessment.Workflow.ExecuteActionAsync(triggerAction)
```

### Resource-based authorization

The permission checked depends on the action, and is composed as a string:

```csharp
if (triggerAction == SendBack || triggerAction == Complete)
    return new OperationAuthorizationRequirement {
        Name = $"{UnitySelector.Review.AssessmentReviewList.Update.Default}.{triggerAction}" };

return new OperationAuthorizationRequirement {
    Name = $"{UnitySelector.Review.AssessmentReviewList.Default}.{triggerAction}" };
```

`AssessmentAuthorizationHandler : AuthorizationHandler<OperationAuthorizationRequirement, Assessment>` then decides. Beyond the AI short-circuit, its key rule is ownership:

```csharp
if (resource.AssessorId == currentUserId || resource.CreatorId == currentUserId) { … }
```

So an assessor can act on their own assessment; acting on someone else's requires the broader permission. This is genuine resource-based authorization — one of the few places in the codebase using ABP's `AuthorizationService.CheckAsync(resource, requirement)` rather than a static policy.

### Scoresheet validation on completion

`IAssessmentScoresheetService.ValidateAnswersOnCompleteAsync(assessmentId, triggerAction)` runs before the transition and blocks `Complete` when the Flex scoresheet is not adequately answered. See [`flex/flex-integration.md`](../flex/flex-integration.md).

## Scores and results

Two scoring systems coexist:

**Flex scoresheets** — the current mechanism. `SaveScoresheetSectionAnswers` persists a section at a time; `AssessmentScoresheetService` owns the integration; the total flows back to `Application.TotalScore`.

**The four fixed fields** — `FinancialAnalysis`, `EconomicImpact`, `InclusiveGrowth`, `CleanGrowth` on the assessment, written by `UpdateAssessmentScore`. That method carries an explicit note about its own state:

```text
Important! Something to do in the future:
   -- need to revisit scoring again post-MVP as right now it is only offline scoring
   -- need to leverage state machine and domain layer during the revisit
```

**Assessment results** are separate again, and live on the *application*, not the assessment: `AssessmentResultStatus`, `AssessmentResultDate`, `RecommendedAmount`, `ApprovedAmount`, `DueDiligenceStatus`, `DeclineRational`. They are written through `GrantApplicationAppService.UpdateAssessmentResultsAsync` under `UnitySelector.Review.AssessmentResults.Update.Default` — see [core-application-lifecycle.md](core-application-lifecycle.md#field-updates-are-tiered-by-permission).

## Reading assessments

| Method | Returns |
|---|---|
| `GetListAsync(applicationId)` | All assessments on an application |
| `GetDisplayList(applicationId)` | The shape the Review List widget renders — assessors, statuses, scores, AI badge |
| `GetCurrentUserAssessmentId(applicationId)` | The caller's own assessment, if any — drives "start my assessment" vs. "open my assessment" |
| `GetPermittedActions(assessmentId)` | The workflow's currently permitted triggers for that assessment |
| `GetActions()` | Every configured trigger, from a throwaway blank assessment |
| `GetWorkflowDiagram()` | A Mermaid graph of the assessment machine |

The surfaces that render this are the **Review List** and **Assessment Scores** widgets, plus **Assessment Results** and its attachments (`Web/Views/Shared/Components/`).
